# P-8 데이터 설계 — 제8장 프롬프트 패키지

> 연결 장: 제8장 데이터 수집 설계 · 워크북: [W-5](../workbook/W5_데이터수집과분석자동화.md)
> 사용법: 복사 → [대괄호] 교체 → 실행 → 검증 프롬프트로 재확인

## 언제 쓰나

연구질문과 대상이 어느 정도 정해졌지만 어떤 방법으로 데이터를 수집할지 결정하지 못한 단계에서 사용한다. 설문·인터뷰·실험·사례연구·로그데이터·2차 데이터·혼합연구 중 어느 것이 가장 적합한지, IRB 신청이 필요한지, 7일 안에 무엇을 준비해야 하는지를 빠르게 정리하고 싶을 때 이 패키지를 꺼낸다.

구체적인 적용 장면:
- 지도교수나 세미나 발표 전에 데이터 수집 방법을 표로 비교해 제출해야 할 때
- IRB 신청 여부를 혼자 판단하기 어려울 때
- 수집 방법을 정했지만 표본 크기·기간·개인정보 위험을 체계적으로 점검하고 싶을 때
- 워크북 W-5 Step 1 작성 전 AI와 함께 초안을 잡을 때

## 프롬프트 1 — 수집 방법 비교

무엇을 얻나: 연구질문에 맞는 7가지 데이터 수집 방법을 한 표로 비교한 결과. 장점·한계·표본(자료량)·수집 기간·IRB 가능성·개인정보 위험·분석방법 적합성·AI 보조 가능 작업·연구자 책임 영역이 포함되며, 1순위와 보조 방법 추천으로 마무리된다.

```text
역할: 당신은 사회과학·공학 연구방법론 전문가이자 데이터 수집 설계 컨설턴트다.

맥락(Context):
- 내 연구질문(RQ): [연구질문을 한 문장으로 입력]
- 연구 대상: [대상 집단·시스템·현상을 구체적으로 입력]
- 연구 트랙: [창업·경영 / 공학·이공 / 인문·사회 중 선택]
- 학위 과정: [석사 / 박사 / 학부 졸업논문]
- 데이터 수집 가용 기간: [예: 2025년 9월~12월, 약 3개월]

과제(Task):
이 연구질문에 적합한 데이터 수집 방법을 아래 7가지로 비교하라.
방법: ① 설문 ② 인터뷰 ③ 실험 ④ 사례연구 ⑤ 로그데이터 ⑥ 2차 데이터 ⑦ 혼합연구

비교 항목(열): 방법명 / 장점 / 한계 / 필요 표본(자료량) / 수집 기간 / IRB 검토 가능성 / 개인정보 위험 수준 / 주요 분석방법 / AI 보조 가능 작업 / 연구자 직접 책임 영역

형식(Format):
1. 비교 표 (9열 × 7행)
2. 추천 요약: 1순위 방법과 보조 방법을 추천하고 이유를 3문장 이내로 설명
3. 7일 안에 준비할 자료 5가지 (번호 목록)

조건(Tone/Guard):
- 한국어 학술 실무체로 작성
- IRB 및 개인정보 항목은 기관·국가 규정에 따라 다를 수 있으므로 [확인 필요]로 표시
- 표본 수·수집 기간 등 수치는 근거 없이 단정하지 말고 "연구 설계에 따라 다름"을 병기
- 이 표는 초안이며 지도교수·연구윤리위원회의 검토가 필요함을 마지막 줄에 명시
```

입력 예시:
- RQ: 스타트업 초기 팀의 심리적 안전감이 제품 피벗 의사결정에 미치는 영향은 무엇인가?
- 대상: 창업 3년 이내 스타트업 공동창업자 및 핵심 팀원
- 트랙: 창업·경영 / 석사 / 수집 기간 3개월

기대 출력(요약):
7가지 방법이 9개 항목으로 정리된 비교 표 + "1순위: 반구조화 인터뷰, 보조: 설문 병행" 형태의 추천 요약 + "IRB 신청서 초안 작성, 인터뷰 가이드 5개 질문 준비, 대상자 목록 10명 이상 확보…" 형태의 7일 준비 목록.

검증 프롬프트:

```text
위 비교 표에서 [선택한 방법명]에 대해 다음을 추가로 확인하라.
1. 이 방법으로 연구질문 [RQ]에 답하기 위해 최소 필요한 표본 수는 몇 명(건)인가?
   G*Power 또는 통계적 근거를 들어 설명하되, 확정값이 아닌 범위로 제시하라.
2. 수집 과정에서 연구자가 직접 처리해야 하는 단계와 AI에 맡길 수 있는 단계를
   단계별 표로 구분하라.
3. 이 방법의 가장 큰 실패 위험 2가지와 그 대비책을 제시하라.
```

## 프롬프트 2 — IRB·개인정보 위험 점검

무엇을 얻나: 연구에서 다루는 정보의 민감도를 동의·익명·민감정보 세 축으로 진단하고, IRB 신청 필요 여부 및 개인정보 처리 절차를 체크리스트 형태로 제공받는다.

```text
역할: 당신은 연구윤리 및 개인정보 보호 전문가다.

맥락(Context):
- 연구 방법: [프롬프트 1에서 선택한 수집 방법]
- 연구 대상: [대상 집단 또는 데이터 유형]
- 수집 정보 예시: [수집할 데이터 항목을 3~5가지 나열]
- 소속 기관 유형: [대학원 / 기업 부설 연구소 / 정부 출연연 등]

과제(Task):
아래 3가지 축으로 연구의 윤리·개인정보 위험을 점검하라.

축 1 — 동의 절차
- 연구 참여 동의서에 반드시 포함해야 할 항목 목록
- 비대면 온라인 동의 시 추가 고려 사항

축 2 — 익명화 수준
- 수집 데이터별 익명화 방법 (가명화 / 완전 익명화 / 집계 처리)
- 재식별 가능성이 있는 항목 표시

축 3 — 민감정보
- 개인정보보호법상 민감정보 해당 여부 [확인 필요]
- 민감정보 처리 시 추가 동의 또는 별도 보관 필요 여부 [확인 필요]

IRB 신청 여부 판단
- 이 연구가 심의 대상인지 간이·면제 심의인지 정규 심의인지 판단 기준을 설명하라.
- 학교·기관마다 다를 수 있으므로 [확인 필요]로 표시하고, 실제 판단은 소속 IRB에 문의하도록 안내

형식(Format):
- 각 축별 체크리스트 (✅ / ⚠️ 기호 사용)
- IRB 판단 흐름도(텍스트 형식)
- 마지막에 "이 점검 결과는 참고용이며 소속 기관 IRB 및 개인정보보호책임자(DPO)의 공식 검토를 받아야 한다"는 안내 문구 포함

조건(Tone/Guard):
- 한국 개인정보보호법 및 생명윤리법 기준으로 작성하되, 국가·기관마다 규정이 다르므로 구체적 조항은 [확인 필요]로 표시
- 법적 조언이 아닌 연구 준비를 위한 참고 자료임을 명시
```

입력 예시:
- 방법: 반구조화 인터뷰(대면, 녹음)
- 대상: 창업 팀원 (성인, 자발적 참여)
- 수집 정보: 직책·연령·창업 경험, 팀 내 갈등 경험, 의사결정 과정 서술
- 기관: 국내 4년제 대학원

기대 출력(요약):
동의서 필수 항목 목록(6~8개), 익명화 방법 표(항목별), 민감정보 해당 여부 [확인 필요] 표시, IRB 간이심의 가능성 흐름도, 소속 IRB 문의 안내.

검증 프롬프트:

```text
위 점검 결과를 바탕으로 아래 시나리오를 추가 검토하라.
시나리오: [예: 인터뷰 참여자가 녹음 거부 시 메모만으로 진행하는 경우]

1. 이 시나리오에서 동의서·익명화·IRB 절차 중 변경이 필요한 항목은 무엇인가?
2. 데이터의 질(신뢰도·타당도)에 미치는 영향을 설명하라.
3. 이 시나리오를 허용할지 판단하는 기준을 연구방법론 관점에서 제시하라.
```

## 프롬프트 3 — 7일 준비 체크리스트 + 표본 수 근거

무엇을 얻나: 데이터 수집 시작까지 7일 안에 완료해야 할 과제를 일자별 체크리스트로 정리하고, 표본 수 결정의 통계적 근거를 확보한다.

```text
역할: 당신은 연구 프로젝트 매니저 겸 연구방법론 조언자다.

맥락(Context):
- 선택한 수집 방법: [방법명]
- 연구질문(RQ): [연구질문]
- 예상 표본 집단: [대상 집단]
- 분석 방법 예정: [예: 다중회귀분석 / 주제분석 / 비교사례분석]
- 현재 준비 상태: [예: IRB 미신청, 설문 도구 미정, 섭외 대상 목록 없음]

과제(Task):
1. 7일 준비 체크리스트
   Day 1~7로 나눠 하루에 완료 가능한 분량으로 과제를 배분하라.
   AI 보조 가능 항목에는 (AI) 표시, 연구자 직접 수행 필수 항목에는 (연구자) 표시.

2. 표본 수 근거
   선택한 분석 방법 기준으로 최소 표본 수를 산출하라.
   - 정량 방법: G*Power 계산식 또는 경험 규칙(rule of thumb) 제시
   - 정성 방법: 이론적 포화(theoretical saturation) 기준 제시
   - 수치는 "최소 X명, 권장 Y명" 형식으로 제시하고 근거 출처(또는 방법론 교과서 표준)를 병기

3. 리스크 완충 계획
   표본 이탈·수집 지연·IRB 지연 등 3가지 리스크에 대한 대비책을 각 2문장으로 제시

형식(Format):
- Day별 체크리스트 표 (날짜 / 과제 / AI·연구자 구분 / 완료 기준)
- 표본 수 산출 근거 블록
- 리스크 완충 계획 목록

조건(Tone/Guard):
- 한국어 실무체
- 하루 과제량은 연구자 1인 기준 2~3시간 이내로 현실적으로 설계
- 표본 수는 확정값이 아님을 명시하고 지도교수·통계 전문가와 최종 확인 권고
- AI가 생성한 설문 문항·인터뷰 가이드는 연구자가 반드시 검토·수정해야 함을 체크리스트 내에 포함
```

입력 예시:
- 방법: 설문(Google Forms, 리커트 5점)
- RQ: MZ세대 직장인의 디지털 자기효능감이 원격근무 성과에 미치는 영향
- 대상: 국내 IT기업 재직자, 25~39세
- 분석: 다중회귀분석
- 현재 상태: IRB 미신청, 기존 척도 탐색 중

기대 출력(요약):
Day 1(기존 척도 문헌 탐색, AI) ~ Day 7(설문 배포 준비 완료, 연구자) 형태의 7일 표 + "최소 100명, 권장 150명 (변수 5개 × 30명 기준)" 형태의 표본 수 블록 + 이탈·지연·IRB 리스크 대비책 3가지.

검증 프롬프트:

```text
위 7일 체크리스트에서 [특정 Day 또는 과제]를 실제로 수행했다고 가정하고 다음을 점검하라.
1. 이 과제의 결과물이 연구방법 장(논문 본문)에 어떻게 서술되어야 하는지 예시 문장 2~3개를 제시하라.
2. 지도교수 면담 시 이 항목에 대해 받을 수 있는 질문 3가지와 예상 답변을 정리하라.
3. 이 체크리스트 전체를 완료했을 때 다음 단계(데이터 수집 시작 또는 IRB 제출)로 넘어가기 위해 추가로 확인해야 할 사항 2가지를 제시하라.
```

## ✅ 연구자 체크

아래 항목을 모두 완료한 후 다음 단계로 진행한다.

- [ ] 프롬프트 1 실행 후 비교 표를 출력해 지도교수 또는 연구 세미나에서 검토받았다
- [ ] 1순위 수집 방법과 보조 방법을 최종 결정했다
- [ ] IRB 신청 필요 여부를 소속 기관 IRB 담당자에게 직접 확인했다 [확인 필요]
- [ ] 개인정보 수집 항목별 익명화 방법을 문서화했다
- [ ] 표본 수 근거를 지도교수 또는 통계 전문가와 확인했다
- [ ] 7일 체크리스트를 워크북 W-5 Step 1에 옮겨 적었다
- [ ] AI가 생성한 설문 문항·인터뷰 가이드를 연구자가 직접 검토·수정했다
- [ ] 데이터셋 1개(가설 또는 실제)를 준비해 5주차 바이브코딩 입력으로 지정했다

## ⚠️ 흔한 실패 패턴

| 실패 패턴 | 왜 문제인가 | 대처법 |
|---|---|---|
| AI가 추천한 표본 수를 근거 없이 그대로 사용 | 연구 설계(변수 수, 검정력, 효과 크기)를 반영하지 않아 통계 심사에서 반려됨 | G*Power 계산 또는 동일 분야 선행 논문 표본 수를 비교해 지도교수와 최종 확인 |
| IRB 신청을 데이터 수집 후로 미룸 | IRB 승인 없이 수집한 데이터는 학위논문 본문에 사용 불가; 재수집 필요 | 수집 방법 결정 직후 IRB 신청 일정 역산; 심의 기간(보통 2~4주) 확보 |
| AI가 생성한 설문 문항을 검토 없이 그대로 배포 | 한 문항에 두 가지 의미 포함, 유도 질문, 변수 조작적 정의와 불일치 등 발생 | 문항별로 "이 문항은 어떤 변수의 어떤 차원을 측정하는가"를 연구자가 직접 대조 |
