# P-5 인용 관리 — 제5장 프롬프트 패키지

> 연결 장: 제5장 Zotero 인용관리 · 워크북: [W-2](../workbook/W2_문헌수집과참고문헌관리.md) · 부록: [부속 나](../appendix/부속자료_나_Zotero_HWP_트러블슈팅.md)
> 사용법: 복사 → [대괄호] 교체 → 실행 → 검증 프롬프트로 재확인

## 언제 쓰나

참고문헌 목록을 완성했거나 Zotero 라이브러리 정리가 끝난 뒤 제출 전 최종 점검 단계에서 쓴다. 세 가지 상황에서 꺼내라.

- 지도교수나 심사위원이 "참고문헌 형식이 틀렸다"고 할까 봐 걱정될 때
- 인용양식을 갑자기 바꿔야 할 때 (APA → IEEE, APA → KCI 등)
- Zotero 자동 수집 후 메타데이터가 빠지거나 이상해 보일 때

> 서지정보 환각 경고: AI는 저자명·연도·DOI·학술지명을 그럴듯하게 지어낸다. 아래 프롬프트는 모두 "임의 생성 금지" 조건을 내장하고 있으나, 출력값을 원문·Zotero·CrossRef에서 직접 대조하는 것은 연구자의 책임이다.

---

## 프롬프트 1 — 참고문헌 오류 탐지 (핵심)

무엇을 얻나: 참고문헌 목록 전체를 지정 양식 기준으로 훑어 오류·누락·위험 항목을 표로 받는다. Zotero에서 수정해야 할 필드와 실행 5단계도 함께 출력된다.

```text
역할(Role): 학술 인용 교정 전문가
맥락(Context): 나는 [학과/전공명] 소속 [학위 과정: 석사/박사] 과정생이며,
[APA 7판 / IEEE / KCI / 학과 자체 양식] 기준으로 참고문헌 목록을 제출해야 한다.
아래는 Zotero에서 내보낸 참고문헌 목록이다.

과제(Task):
1. 아래 참고문헌 목록을 [APA 7판 / IEEE / KCI / 학과 자체 양식] 기준으로 항목별로 점검하라.
2. 다음 항목을 표로 정리하라.
   | 번호 | 저자·제목(요약) | 문제 유형 | 구체적 오류 내용 | 권장 수정 방향 |
   문제 유형은 다음 중 하나 이상으로 표기한다:
   [누락 정보 / 형식 오류 / 중복 가능성 / DOI·URL 확인 필요 / 2차 인용 가능성 / 실제 존재 여부 확인 필요]
3. 각 항목에 대해 Zotero에서 수정해야 할 필드명을 명시하라.
4. 마지막에 "참고문헌 정리 실행 5단계"를 제시하라.

제약(Format/Constraints):
- 저자명·연도·DOI·학술지명을 절대 임의로 생성하지 말라.
- 불확실한 정보는 반드시 [확인 필요]로 표시하라.
- 오류가 없는 항목은 "정상"으로 표기하고 수정 제안을 생략하라.
- 결과는 한국어로 작성하라.

[참고문헌 목록을 여기에 붙여넣기]
```

입력 예시:

> 홍길동 (2021). AI 기반 자연어 처리 연구. 한국정보과학회논문지, 48(3), 125-140.
> Smith, J. (2020). Deep learning for NLP. Journal of AI Research.
> 이영희 외 (2022). 머신러닝 응용. 정보과학회지, 49(2).

기대 출력(요약):

| 번호 | 저자·제목(요약) | 문제 유형 | 구체적 오류 내용 | 권장 수정 방향 |
|------|-----------------|-----------|-----------------|----------------|
| 2 | Smith (2020) | 누락 정보, DOI·URL 확인 필요 | 권호·페이지 없음, DOI 미기재 | Zotero 필드: Volume, Pages, DOI 입력 필요. [확인 필요] |
| 3 | 이영희 외 (2022) | 누락 정보 | 페이지 없음 | Zotero 필드: Pages 입력 필요 |

→ 참고문헌 정리 실행 5단계(AI 출력 예시): ① Zotero에서 [확인 필요] 항목 필터링 → ② CrossRef(doi.org)에서 DOI 직접 조회 → ③ Zotero 필드 수동 수정 → ④ Better BibTeX export 재실행 → ⑤ Word/HWP에 붙여넣기 후 양식 재확인

검증 프롬프트:

```text
위 오류 표에서 "실제 존재 여부 확인 필요"로 표시된 항목만 다시 나열하라.
각 항목에 대해 내가 직접 확인할 수 있는 구체적인 방법(검색 키워드, 데이터베이스 URL)을 제시하라.
어떤 경우에도 DOI나 URL을 새로 생성하거나 추측하지 말라.
```

## 프롬프트 2 — Zotero 필드 수정 가이드

무엇을 얻나: 특정 참고문헌 항목의 Zotero 필드를 어떻게 채워야 하는지 단계별 안내를 받는다. Zotero 인터페이스 용어 그대로 제시되므로 바로 따라 할 수 있다.

```text
역할(Role): Zotero 사용 전문 연구 보조원
맥락(Context): 나는 Zotero 7을 사용하며 [APA 7판 / IEEE / KCI] 양식으로 참고문헌을 관리한다.
아래 항목의 메타데이터가 불완전하다.

과제(Task):
1. 아래 인용 정보를 분석하고, Zotero에서 어느 필드에 무슨 값을 입력해야 하는지 표로 정리하라.
   | Zotero 필드명 | 현재 값 | 입력해야 할 값 또는 확인 방법 |
2. 필드 입력 후 [APA 7판 / IEEE / KCI] 기준 올바른 서지 형식을 보여주어라.
3. DOI가 있는 경우 doi.org/[DOI]로 직접 확인하라고 안내하라. DOI를 추측하거나 새로 만들지 말라.

제약(Format/Constraints):
- Zotero 7 인터페이스의 실제 필드명(Item Type, Title, Author, Year, Journal, Volume, Issue, Pages, DOI, URL, Publisher, Place 등)을 그대로 사용하라.
- 모르는 값은 [확인 필요 — CrossRef / Google Scholar / 원문 직접 조회]로 표시하라.
- 추측으로 값을 채우지 말라.

[불완전한 인용 정보를 여기에 붙여넣기]
```

입력 예시:

> Kim, S. et al. AI model evaluation. IEEE Trans., vol. 12, 2023.

기대 출력(요약):

| Zotero 필드명 | 현재 값 | 입력해야 할 값 또는 확인 방법 |
|--------------|---------|-------------------------------|
| Author | Kim, S. et al. | 공저자 전체 이름 [확인 필요 — 원문 직접 조회] |
| Journal | IEEE Trans. | 전체 학술지명 [확인 필요 — IEEE Xplore] |
| Issue | 없음 | [확인 필요 — IEEE Xplore] |
| Pages | 없음 | [확인 필요 — IEEE Xplore] |
| DOI | 없음 | [확인 필요 — doi.org 또는 IEEE Xplore] |

검증 프롬프트:

```text
위 표에서 내가 직접 입력해야 하는 필드와 자동으로 채울 수 있는 필드를 구분하라.
Zotero의 "Add Item by Identifier(DOI/ISBN)" 기능으로 자동 수집이 가능한지 판단하고, 가능하다면 그 절차를 안내하라.
```

## 프롬프트 3 — 인용 양식 변환 (APA ↔ IEEE ↔ KCI)

무엇을 얻나: 참고문헌 목록 전체 또는 개별 항목의 인용 양식을 다른 양식으로 변환한다. 변환 결과와 함께 주의해야 할 차이점도 표로 받는다.

```text
역할(Role): 학술 인용 양식 변환 전문가
맥락(Context): 나는 [출발 양식: APA 7판 / IEEE / KCI] 형식으로 작성된 참고문헌 목록을
[도착 양식: APA 7판 / IEEE / KCI / 학과 자체 양식]으로 변환해야 한다.

과제(Task):
1. 아래 참고문헌 목록을 [도착 양식] 기준으로 변환하라.
2. 두 양식 사이의 주요 차이점(저자명 형식·연도 위치·제목 대소문자·학술지 약어 여부·DOI 표기 방식 등)을 표로 정리하라.
3. 변환 중 원본 정보만으로 확정할 수 없어 [확인 필요]로 남긴 항목을 별도로 나열하라.

제약(Format/Constraints):
- 저자명·연도·DOI·학술지명을 절대 임의로 수정하거나 새로 만들지 말라.
- IEEE 양식의 학술지 약어가 불확실하면 [확인 필요 — IEEE Abbreviations List]로 표시하라.
- KCI 양식 적용 시 국문 저자는 성명 전체를 유지하라. 영문화하지 말라.
- 변환 결과는 Zotero에서 다시 한 번 검증하도록 안내하라.

[변환할 참고문헌 목록을 여기에 붙여넣기]
```

입력 예시 (APA → IEEE):

> Bengio, Y., LeCun, Y., & Hinton, G. (2021). Deep learning for AI. *Communications of the ACM*, *64*(7), 58–65. https://doi.org/10.1145/3448250

기대 출력(요약):

IEEE 변환 결과:
> Y. Bengio, Y. LeCun, and G. Hinton, "Deep learning for AI," *Commun. ACM*, vol. 64, no. 7, pp. 58–65, Jul. 2021, doi: 10.1145/3448250.

주요 차이점 표:

| 항목 | APA 7판 | IEEE |
|------|---------|------|
| 저자명 | Last, F. M. | F. M. Last |
| 연도 위치 | 저자명 직후 (괄호) | 제목 뒤 |
| 제목 대소문자 | 첫 단어만 대문자 | 첫 단어만 대문자 |
| 학술지명 | 이탤릭체 전체 | 약어 이탤릭체 |
| DOI | https://doi.org/... | doi: ... |

검증 프롬프트:

```text
변환된 목록에서 학술지 약어를 사용한 항목을 모두 나열하라.
각 항목에 대해 IEEE Abbreviations List(https://ieeeauthorcenter.ieee.org/create-your-article/tools-and-templates/ieee-publication-finder/)에서 직접 확인해야 한다고 안내하라.
약어를 추측하거나 새로 만들지 말라.
```

## ✅ 연구자 체크

프롬프트 실행 후 아래 항목을 직접 점검하라.

- [ ] AI 출력의 저자명이 원문과 일치하는가?
- [ ] 연도가 실제 출판 연도와 같은가? (개정판·재출판 주의)
- [ ] DOI를 doi.org에 직접 입력했을 때 해당 논문으로 연결되는가?
- [ ] 학술지명·권호·페이지가 Zotero 라이브러리와 일치하는가?
- [ ] "[확인 필요]" 표시 항목을 모두 처리했는가?
- [ ] 2차 인용 항목에 `(원저자, 연도, as cited in 인용자, 연도)` 형식을 적용했는가?
- [ ] Zotero에서 최종 양식으로 다시 export해 Word/HWP에 붙여넣었는가?

> 서지정보 환각 경고: AI는 존재하지 않는 DOI, 틀린 저자명, 없는 권호를 그럴듯하게 생성한다. AI 출력을 복사해 제출하기 전에 반드시 CrossRef(doi.org), Google Scholar, RISS, DBpia 중 하나에서 원문을 직접 확인하라. "그 논문이 있을 것 같다"는 느낌은 검증이 아니다.

## ⚠️ 흔한 실패 패턴

| 실패 패턴 | 원인 | 대처 방법 |
|-----------|------|-----------|
| AI가 없는 DOI를 생성함 | 서지정보 환각 | 모든 DOI를 doi.org에서 직접 입력 확인 |
| 학술지 약어가 틀림 (IEEE 양식) | 약어 추측 | IEEE Abbreviations List에서 직접 조회 |
| 변환 후 저자 순서가 바뀜 | 양식 혼동 | Zotero 원본 항목의 Author 필드와 대조 |
