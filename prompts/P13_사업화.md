# P-13 사업화 — 제13장 프롬프트 패키지

> 연결 장: 제13장 연구성과 사업화 전략 · 워크북: [W-8](../workbook/W8_연구성과사업화전략.md) · 부록: [D](../appendix/D_정부과제캘린더.md)·[E](../appendix/E_5대활용트랙비교표.md)·[부속 마](../appendix/부속자료_마_사업화의사결정시트.md)
>
> 사용법: 복사 → [대괄호] 교체 → 실행 → 검증 프롬프트로 재확인

---

## 언제 쓰나

- 학위논문 결과를 사업계획서·정부 R&D 제안서로 전환해야 할 때
- 린 캔버스 9블록을 연구결과로 채워야 할 때
- 지도교수·평가위원·투자자 앞에서 같은 연구를 다르게 발표해야 할 때
- 5대 정부 R&D 트랙 중 본인에게 맞는 트랙을 1개 선정하고 제안서 항목을 매핑해야 할 때

> 핵심 원칙: 시장 규모·예산·매출·성과지표 숫자는 AI가 임의로 생성하지 않는다. 모두 `[확인 필요]`로 표시한 뒤 연구자가 직접 조사·기입한다.

## 프롬프트 1 — 연구 → 사업화 통합 변환

무엇을 얻나: 학위논문 요약을 사업계획서·정부 R&D 제안서 관점으로 동시에 변환한 종합 출력. 핵심 기여 3문장, 문제-솔루션 프레임, 린 캔버스 9블록, 정부과제 7항목, 청중별 1분 발표 첫 문장을 한 번에 산출한다.

```text
역할(Role): 사업화 컨설턴트 겸 정부 R&D 제안서 전문가
맥락(Context): 나는 학위논문을 완성했으며, 이를 사업계획서와 정부 R&D 제안서로 확장하려 한다.
과제(Task): 아래 학위논문 요약을 사업계획서·정부 R&D 제안서 관점으로 변환하라.

[입력 정보]
- 연구주제: [주제]
- 주요 결과: [결과]
- 학술적 기여: [기여]
- 실무적 함의: [함의]

[출력 형식(Format)]
1. 핵심 기여 3문장 (기존 한계 / 본 연구의 방법 / 달성한 성과 순서로 각 1문장)
2. 사업화 전환 프레임 (아래 6개 항목을 각 2~3문장으로)
   - 해결할 문제
   - 고객(수혜자)
   - 기존 해결책의 한계
   - 제안 솔루션
   - 차별성
   - 기대효과
3. 린 캔버스 9블록 (블록별 2~4줄 요약)
4. 정부과제 7항목 (필요성·목표·내용·방법·일정·기대효과·예산)
5. 청중별 1분 발표 첫 문장 (지도교수 / 평가위원 / 투자자 각 1문장)

[할루시네이션 방지 조건]
- 시장 규모·예산·매출·성과지표(수치)는 절대 임의로 생성하지 마라.
- 수치가 필요한 모든 항목은 [확인 필요]로 표시하라.
- 제시된 [입력 정보] 외의 사실을 추론하거나 단정하지 마라.
```

입력 예시:
- 연구주제: 중소 제조기업의 ESG 공시 자동화를 위한 자연어처리 기반 보고서 생성 모델
- 주요 결과: 제안 모델이 기존 수작업 대비 보고서 작성 시간을 68% 단축, F1-score 0.87 달성
- 학술적 기여: ESG 비정형 데이터를 GRI 항목으로 자동 매핑하는 프레임워크 최초 제안
- 실무적 함의: 전담 인력 없는 중소기업도 연 1회 ESG 보고서 발행 가능

기대 출력(요약):
- 핵심 기여 3문장: "기존 ESG 공시 도구는 대기업 전용으로 중소기업 적용이 불가능했다. / 본 연구는 NLP 기반 자동 매핑 프레임워크로 GRI 항목을 비정형 데이터에서 추출한다. / 실험 결과 작성 시간 68% 단축·F1-score 0.87을 달성했다."
- 린 캔버스 블록 ①~⑨ 요약 (⑤·⑥·⑦ 수치는 전부 [확인 필요])
- 지도교수용: "기존 연구의 한계를 NLP 자동 매핑으로 해결한 결과 F1-score 0.87을 얻었습니다."
- 평가위원용: "이 과제는 평가지표 필요성·차별성·기대효과 항목에 직접 부합하고, [가점 항목 확인 필요]를 충족합니다."
- 투자자용: "중소기업 ESG 공시 시장은 [확인 필요] 규모이며, 본 솔루션은 기존 대비 비용을 [확인 필요] 절감합니다."

검증 프롬프트:

```text
위 출력에서 구체적인 숫자(시장 규모, 예산, 매출, 성장률, 고용 인원)가 [확인 필요] 없이 등장한 항목이 있으면 모두 찾아서 목록으로 제시하라. 확인되지 않은 수치는 [확인 필요]로 교체하라.
```

## 프롬프트 2 — 린 캔버스 9블록 변환 (핵심 집중)

무엇을 얻나: 학위논문 각 챕터를 린 캔버스 9블록에 정밀 매핑한 1쪽짜리 사업계획서 초안. 논문에서 가져올 수 있는 블록과 신규 작성이 필요한 블록을 명확히 구분한다.

```text
역할(Role): 린 스타트업 방법론 전문가
맥락(Context): 나는 완성된 학위논문을 린 캔버스로 변환하려 한다.
과제(Task): 아래 학위논문 정보를 바탕으로 린 캔버스 9블록을 채워라.

[학위논문 정보]
- Introduction (연구 배경·문제 정의): [내용]
- Method (제안 방법론): [내용]
- Result / Experiment (실험 결과·지표): [내용]
- Contribution (학술적 기여): [내용]
- Discussion (실무 적용·시장 논의): [내용]

[출력 형식(Format)]
아래 9블록 각각을 표 형식으로 출력하라.
| 블록 번호 | 블록명 | 내용 (2~5줄) | 출처 (논문 챕터 또는 신규 작성) |

① Problem — 해결할 문제 3가지
② Customer Segments — 주요 고객·수혜자
③ Unique Value Proposition — 핵심 가치 제안 (한 문장)
④ Solution — 제안 방법론·기술
⑤ Channels — 고객 접근 경로
⑥ Revenue Streams — 수익 구조
⑦ Cost Structure — 주요 비용 항목
⑧ Key Metrics — 핵심 성과지표
⑨ Unfair Advantage — 경쟁 불가 우위 (학위·실적 포함)

[할루시네이션 방지 조건]
- ⑤·⑥·⑦ 블록의 금액·비율·건수는 [확인 필요]로만 표시하라.
- 내가 제공하지 않은 시장 데이터, 경쟁사 이름, 특허 정보를 추가하지 마라.
- 블록이 논문에서 도출 불가능한 경우 "신규 작성 필요 — [작성 지침]"으로 안내하라.
```

입력 예시:
- Introduction: "국내 중소 제조기업의 87%가 ESG 공시 전담 인력 없음. GRI 표준 요구 항목 72개 수작업 작성에 평균 [확인 필요] 시간 소요."
- Method: "BERT 기반 다중 레이블 분류 + GPT 기반 문장 생성 2단계 파이프라인"
- Result: "F1-score 0.87, 작성 시간 68% 단축, 인간 평가자 만족도 4.2/5"
- Contribution: "GRI 비정형 데이터 자동 매핑 프레임워크 최초 제안"
- Discussion: "중소기업 컴플라이언스 서비스 SaaS 모델 가능성 언급"

기대 출력(요약):
- ①~④, ⑧, ⑨: 논문 챕터에서 직접 도출된 내용으로 채워짐
- ⑤·⑥·⑦: "신규 작성 필요" 안내 + 수치는 전부 [확인 필요]
- ③ UVP 예시: "ESG 공시 전담 인력 없는 중소 제조기업이 GRI 보고서를 자동 생성하도록 돕는 NLP 파이프라인"

검증 프롬프트:

```text
위 린 캔버스에서 ① Problem, ③ UVP, ④ Solution이 논리적으로 연결되는지 확인하라. 고객(②)이 겪는 문제(①)를 솔루션(④)이 해결하고, 그 가치가 UVP(③)에 담겨 있는가? 불일치하는 블록이 있으면 수정안을 제시하라.
```

## 프롬프트 3 — 청중별 1분 발표문 작성 (지도교수·평가위원·투자자)

무엇을 얻나: 같은 연구를 세 청중에게 맞춰 재구성한 1분 발표 스크립트 초안. 청중마다 강조점·구조·단어 선택이 달라지는 이유를 함께 설명한다.

```text
역할(Role): 과학 커뮤니케이터 겸 투자 IR 전문가
맥락(Context): 나는 동일한 연구를 세 가지 다른 청중 앞에서 각각 1분 안에 발표해야 한다.
과제(Task): 아래 연구 정보를 바탕으로 청중별 1분 발표문(약 150~180자, 3~4문장)을 작성하라.

[연구 정보]
- 연구주제: [주제]
- 핵심 방법: [방법]
- 주요 결과: [결과]
- 학술적 기여: [기여]
- 사업화 가능성: [가능성 또는 "미검토"]

[청중별 출력 형식(Format)]
각 청중에 대해 아래 형식으로 출력하라.

### [청중명]
그들이 보는 것: (한 줄 요약)
발표문: (3~4문장, 150~180자)
강조 전략: (이 버전에서 무엇을 앞세웠는지 1~2줄 설명)

청중 3종:
1. 지도교수 — 학술적 기여·방법론 엄밀성을 본다
2. 정부과제 평가위원 — 필요성·차별성·평가지표 정합성·가점 항목을 본다
3. 투자자 — 시장 문제·수익 모델·팀 역량을 본다

[할루시네이션 방지 조건]
- 투자자용 발표문의 시장 규모·매출·수익률 수치는 [확인 필요]로만 표시하라.
- 평가위원용 발표문의 가점 항목은 내가 확인하지 않은 항목을 단정하지 마라. [해당 여부 확인 필요]로 표시하라.
- 발표문에 없는 실적(특허·논문·수상)을 추가하지 마라.
```

입력 예시:
- 연구주제: 중소 제조기업 ESG 공시 자동화 NLP 모델
- 핵심 방법: BERT+GPT 2단계 파이프라인
- 주요 결과: F1-score 0.87, 작성 시간 68% 단축
- 학술적 기여: GRI 자동 매핑 프레임워크 최초 제안
- 사업화 가능성: SaaS 모델 검토 중

기대 출력(요약):

| 청중 | 첫 문장 예시 |
|---|---|
| 지도교수 | "기존 ESG 공시 연구는 대기업 수작업 중심이었으나, 본 연구는 NLP 2단계 파이프라인으로 GRI 항목 자동 매핑을 최초 제안하여 F1-score 0.87을 달성했습니다." |
| 평가위원 | "이 과제는 중소기업 ESG 공시 의무화라는 정책 필요성에 직접 부합하며, 제안 기술의 차별성과 [가점 항목 해당 여부 확인 필요]를 갖추고 있습니다." |
| 투자자 | "중소 제조기업 ESG 공시 시장은 [확인 필요] 규모이며, 본 솔루션은 기존 수작업 대비 비용을 [확인 필요] 절감하는 SaaS 서비스로 전환 가능합니다." |

검증 프롬프트:

```text
위 세 발표문이 동일한 연구에서 나온 것임에도 청중마다 강조점이 달라졌는지 확인하라. 세 발표문에서 공통으로 사용된 핵심 키워드를 추출하고, 각 청중별로 추가·제거된 요소를 표로 비교하라.
```

## ✓ 연구자 체크 — 숫자 환각 금지

AI 출력물을 제출 전 반드시 아래 항목을 직접 확인한다. `[확인 필요]` 표시가 남아 있는 항목은 제출 불가.

| 확인 항목 | 확인 방법 | 완료 여부 |
|---|---|---|
| 시장 규모 (TAM·SAM·SOM) | 통계청·KEIT·산업연구원 보고서 인용 | ☐ |
| 정부과제 예산 (자기부담금 포함) | 해당 사업 공고문 원본 확인 | ☐ |
| 가점 항목 해당 여부 | 공고문 가점 조항 직접 대조 | ☐ |
| 성과지표 (논문·특허·매출·고용) | 사업 지침서 양식 기준으로 작성 | ☐ |
| 연구책임자 자격 | 지도교수 또는 소속 기관 산학협력단 확인 | ☐ |
| 기관 동의 일정 | 소속 기관 처리 기간 2주 이상 확보 | ☐ |

## ※ 흔한 실패 패턴

| 실패 패턴 | 증상 | 해결 방법 |
|---|---|---|
| 숫자 환각 | AI가 "국내 시장 규모 약 2조 원", "ROI 320%" 등 근거 없는 수치를 생성함 | 프롬프트에 할루시네이션 방지 조건 명시 후 재실행; 검증 프롬프트로 수치 전수 점검 |
| 청중 혼합 | 투자자용 발표문에 학술 용어, 평가위원용에 수익 모델이 섞임 | 청중별 "그들이 보는 것" 한 줄을 먼저 고정한 뒤 발표문 작성 요청 |
| 린 캔버스 블록 공백 | ⑤·⑥·⑦ (채널·수익·비용)이 논문에서 도출되지 않아 빈칸으로 남음 | 정상 패턴으로 인식; W-8 Step 1 양식에서 별도 사업화 의사결정으로 처리 |
