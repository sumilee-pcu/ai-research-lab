# 부록 F. 하네스 엔지니어링
### 24시간 일하는 AI 특급 연구원을 고용하는 법

> **연결 장:** 제4~13장 (특히 6·7·9·13장) &nbsp;|&nbsp; **도구:** Claude Code &nbsp;|&nbsp; **성격:** 심화 실습 / 자료실 전용
>
> ⚠️ 이 부록은 **선택 심화 자료**입니다. 본문 1~13장을 한 번 익힌 독자가 "한 챕터씩 수동으로 하던 작업을 **엘리트 사원 팀**에게 한 번에 맡기는" 단계로 올라설 때 읽으세요. (최종 점검: 2026-06-09)

---

## 도입: 하네스란 무엇인가

이 책은 문헌 검색(6장) → 독해(4장) → 인용(5장) → 설계(7장) → 분석(9장) → 집필(11·12장) → 사업화(13장)의 순서로, **연구자가 AI를 한 단계씩 부리는 법**을 가르친다.

**하네스(harness)** 는 이 단계들을 **여러 전문 에이전트(AI 역할)에게 나눠 맡기고, 한 번의 지시로 협업시키는 설정 묶음**이다. 프롬프트가 "이번 한 번 이렇게 해줘"라는 1회성 지시라면, 하네스는 **직무기술서를 받고 출근하는 정식 사원**이다. 같은 일을 매번 같은 절차·같은 품질로, 자기검증까지 거쳐 처리한다. 범용 AI를 이렇게 특정 직무에 맞게 설계·조립하는 일이 곧 **하네스 엔지니어링**이다. 도구는 **Claude Code**(터미널·데스크탑형 바이브코딩 환경, 9.2절 참고)를 사용한다.

> 📌 이렇게 생각하라 — 나는 **1인 리서치 센터의 센터장**이고, 아래 세 하네스는 내가 채용한 **엘리트 사원 3인방**이다. 혼자 13장을 끌고 가는 대신, 전문 사원에게 직무를 위임하고 나는 검수·판단에 집중한다.

이 부록에서 소개하는 세 하네스는 공개 저장소 [`github.com/revfactory/harness-100`](https://github.com/revfactory/harness-100)의 한국어 사례 중 연구·집필에 직접 맞닿은 세 개다.

| 엘리트 사원 | 하네스(저장소 ko/) | 한 줄 직무 | 책 연계 |
|---|---|---|---|
| 📚 **문헌조사원** | `63-research-assistant` | 문헌 검색·정리·종합 | 4·5·6장 (제2부) |
| ✍️ **논문집필가** | `98-academic-paper` | 연구설계→분석→집필→투고 | 7~12장 (제2·3부) |
| 🏛️ **정부과제 기획자** | `45-gov-funding-plan` | 사업계획서·정부 R&D | 13장 (제4부) |

> 📌 한눈에 보는 지도: **[그림 F-1. AI 연구 하네스 ↔ 단원 지도](F_하네스_단원지도.png)**

## 1. 설치 (공통)

세 하네스 모두 구조가 같다. 저장소에서 해당 폴더의 **`.claude/`** 안에 있는 세 가지를 작업 프로젝트의 `.claude/`로 복사하면 끝이다.

```
.claude/
├── agents/      ← 전문 에이전트 5명 (각 .md)
├── skills/      ← 오케스트레이터 + 도메인 스킬 3개
└── CLAUDE.md    ← 팀 조율 규칙
```

> ⚠️ **하나의 `.claude/`에는 하네스 하나만.** 각 하네스가 자기 `CLAUDE.md`(팀 규칙)를 갖고 있어, 둘을 한 폴더에 합치면 충돌한다. 하네스마다 **별도 폴더**를 만들어 설치하라.

용량은 하네스당 약 50KB(텍스트 설정 파일)에 불과하다. 결과물(`_workspace/`)도 마크다운 텍스트라 부담이 없다.

## 2. 세 하네스 상세

### ① 문헌 하네스 (research-assistant)

- **시작:** `/research-assistant` 또는 "OOO에 대한 문헌 리뷰를 해줘. APA 형식으로"
- **에이전트 5:** 문헌검색 · 메모작성 · 비평종합 · 참고문헌관리 · 연구조율(QA)
- **워크플로우:** 문헌검색 → (읽기메모 ∥ 참고문헌 초안) → 비평·종합 → 참고문헌 최종 → 품질검증
- **산출물(`_workspace/`):** `01_literature_search` → `02_reading_notes` → `03_critical_synthesis` → `04_bibliography`(APA) → `05_research_summary`

| 에이전트 | 본문 연계 |
|---|---|
| 문헌검색 | **6장** 트렌드 탐색 · 6.4 Research Gap |
| 메모작성 | **4장** AI PDF 독해 (NotebookLM·SciSpace, 8칸 독해표) |
| 비평종합 | **6.4** Research Gap → 키워드 트리 |
| 참고문헌 | **5장** Zotero 인용관리 · 5.3 APA·IEEE·KCI |

### ② 논문 하네스 (academic-paper)

- **시작:** `/academic-paper` 또는 "OOO를 연구하는 논문을 써줘"
- **에이전트 5:** 연구설계 · 실험관리 · 통계분석 · 논문집필 · 투고준비
- **워크플로우:** 연구설계 → 실험프로토콜 → 통계분석(코드·APA표) → IMRaD 집필 → 투고패키지 → 통합리뷰
- **산출물:** `01_research_design` → `02_experiment_protocol` → `03_analysis_report` → `04_manuscript` → `05_submission_package` → `06_review_report`

| 에이전트 | 본문 연계 |
|---|---|
| 연구설계 | **7장** IMRaD 2.0 · 7.3 질문↔가설↔방법론 정합성 |
| 실험관리 | **8장** 데이터 수집 설계 · 8.4 공학 트랙 · 8.5 IRB |
| 통계분석 | **9장** 바이브코딩 분석 + **10장** 시각화(Table·Figure) |
| 논문집필 | **11장** 결과 해석·논의 (Discussion 5단 구조) |
| 투고준비 | **12장** 학술글쓰기 윤리 · 12.4 저널 스타일 · 12.6 재현성 패키지 |

### ③ 정부과제 하네스 (gov-funding-plan)

- **시작:** `/gov-funding-plan` 또는 "정부지원사업 사업계획서 써줘"
- **에이전트 5:** 공고분석 · 기술작성 · 사업작성 · 예산편성 · 제출검토
- **워크플로우:** 공고분석 → 기술계획 → 사업계획 → 예산편성 → 종합검토
- **본문 연계:** **13장** 연구성과 사업화 · 13.5 공고문 읽는 법 · **7.4** IMRaD↔사업계획서↔정부과제 매핑

## 3. 권장 사용 흐름 (① → ② → ③)

세 하네스는 **하나의 연구주제를 단계적으로 확장**하도록 이어진다. 이는 13장과 부록 E(5대 활용 트랙)의 "하나의 주제, 여러 갈래" 원칙을 자동화 도구로 구현한 것이다.

1. **① 문헌 하네스** — 주제를 넣고 선행연구·Research Gap을 정리한다. → `05_research_summary`의 연구 갭을 확보.
2. **② 논문 하네스** — 그 연구 갭을 입력으로 설계→분석→집필을 진행한다. → IMRaD 원고 + 투고패키지.
3. **③ 정부과제 하네스** — 완성된 연구를 사업계획서·R&D 제안서로 변환한다. → 13장 사업화 산출물.

> 💡 **핵심:** 연구 내용을 새로 만들지 않는다. ①의 결과가 ②의 입력이 되고, ②의 결과가 ③의 입력이 된다. 프레임만 바뀐다.

---

## 4. 정직하게 쓰기 — 하네스의 한계 (3.5·12.5절 연계)

하네스는 **연구를 대신하지 않는다.** 초안·구조·코드를 빠르게 만들 뿐, 다음은 반드시 연구자가 책임진다.

- **검증:** 하네스가 제시한 문헌의 서지정보는 원문에서 재확인하라. (산출물에 `[확인 필요]` 태그가 그대로 남는다 → 3.5 할루시네이션 방지)
- **데이터:** 논문 하네스는 분석 **코드와 전략**을 만들지만 **실제 데이터 수집·통계 실행**은 연구자의 몫이다. 데이터 없이 나온 수치는 예시일 뿐이다.
- **AI 명시:** 하네스로 작성한 부분은 투고 시 AI 사용을 명시하라. (12.5절, 부록 [라](부속자료_라_AI사용명시문구.md))
- **윤리:** IRB·저작권·표절 검토는 자동화 대상이 아니다. (8.5·12.5절)

## 5. 실습 과제

> 본인 연구주제 한 문장으로 ①→② 흐름을 한 번 돌려보고, 산출물을 본문 해당 장의 결과물과 비교한다.

1. 폴더 두 개(`문헌`, `논문`)를 만들고 각각 ①·② 하네스를 설치한다.
2. `문헌` 폴더에서 `/research-assistant` → 주제 입력 → `_workspace/` 5개 산출물 확인.
3. `05_research_summary`의 연구 갭을 복사해 `논문` 폴더의 `/academic-paper`에 입력.
4. 나온 `04_manuscript`를 **7장 목차 5원칙·11장 Discussion 5단 구조**로 직접 점검·수정한다.
5. (심화) 결과를 ③ 정부과제 하네스에 넣어 13장 린 캔버스/제안서로 변환한다.

> 📂 참고용 **샘플 산출물**(문헌 리뷰 6종 + 논문 7종, 주제: 「LLM 기반 단위 테스트 생성」)이 워크숍 자료로 제공된다. 형식·정직한 한계 표기를 미리 볼 수 있다.
