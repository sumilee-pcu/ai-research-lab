# W-4 IMRaD 목차와 사업화 매핑

> 연결 장: 제7장 · 연결 프롬프트: [P-7](../prompts/P07_목차설계.md)
> 이 워크북을 마치면: 3수준 목차 + 섹션 개요 + 사업화 매핑표

---

## 사용법

1. **Step 1**부터 순서대로 진행하되, 이미 명확한 항목은 건너뛰어도 됩니다.
2. **빈 표·빈칸**에는 자신의 연구 내용을 직접 기입하세요. 예시 텍스트는 `[이렇게]` 표기되어 있습니다.
3. 각 Step 끝에 연결 프롬프트 링크가 있습니다. AI에게 초안을 요청할 때 해당 프롬프트를 먼저 읽고 사용하세요.
4. 완료 기준은 마지막 **완료 체크리스트**를 모두 체크하는 것입니다.
5. 작성 소요 시간: 60~90분 (AI 보조 시 30~45분)

## Step 1. RQ·가설·데이터·분석 정합성 점검

**목적** — 목차를 설계하기 전에 연구의 핵심 요소들이 서로 맞물리는지 확인합니다. 정합성이 흔들리면 아무리 정교한 목차도 논리 구조가 무너집니다.

## Step 2. IMRaD 3수준 목차

**목적** — 논문의 뼈대를 3수준(장 → 절 → 항)으로 설계합니다. 각 섹션마다 **핵심 주장 문장**과 **필요 자료**를 함께 기입하면 집필 시 방향을 잃지 않습니다.

> **IMRaD 구조**: Introduction → Related Work → Methods → Results → Discussion → Conclusion

---

## Step 4. 논문 → 사업계획서 → 정부과제 매핑표

**목적** — 논문의 각 구성요소가 사업계획서와 정부과제 신청서의 어느 항목으로 재활용될 수 있는지 미리 매핑해 둡니다. 논문 작성 단계부터 사업화를 염두에 두면 문서 재활용률이 크게 높아집니다.

### 4-1. 핵심 매핑표

| 논문 항목 | 핵심 내용 요약 (직접 기입) | 사업계획서 항목 | 정부과제 항목 |
|----------|------------------------|--------------|------------|
| 연구 배경·필요성 (1.1~1.2) | | 사업 배경 및 필요성 | 연구개발 필요성 |
| 연구 목적·질문 (1.3) | | 사업 목표 | 최종 목표 |
| 관련 연구·기술 동향 (2장) | | 시장 동향 분석 | 기술 동향 및 수준 |
| 연구 방법·설계 (3장) | | 사업 추진 방법 | 연구개발 내용 및 방법 |
| 데이터·도구 (3.2~3.3) | | 기술 스택·인프라 | 연구시설·장비 현황 |
| 주요 결과 (4장) | | 기술 성능 지표 | 성과지표 (정량) |
| 이론적 함의 (5.3) | | 기술적 차별성 | 기술의 독창성·우수성 |
| 실무적 함의 (5.4) | | 시장 적용 방안 | 활용 방안 |
| 연구 한계 (5.5) | | 리스크 및 대응 방안 | 연구개발 위험 요소 |
| 향후 연구 (6.3) | | 사업 확장 로드맵 | 후속 연구 계획 |

### 4-2. 재활용 가능 콘텐츠 목록

논문 작성 중 아래 산출물을 별도 파일로 저장해 두면 사업 서류 작성 시 즉시 재활용할 수 있습니다.

| 재활용 콘텐츠 | 저장 위치 (직접 기입) | 재활용 예정 문서 |
|-------------|-------------------|---------------|
| 문제 정의 단락 (1~2쪽) | | 사업계획서·과제신청서 |
| 기술 동향 요약 (표 또는 그림) | | 시장 분석·기술 동향 |
| 연구 방법 흐름도 | | 추진 방법 섹션 |
| 핵심 결과 수치·그래프 | | 성과지표·KPI |
| 비교 분석표 (기존 기술 vs. 제안 기술) | | 차별성·우수성 |
| 한계 및 개선 방향 | | 리스크 관리 |

> **가이드** — 정부과제 항목명은 부처·사업마다 다를 수 있습니다. IITP, NRF, KEIT 등 지원 기관의 공고문을 확인하고 항목명을 맞춤 수정하세요.

> **연결 프롬프트** — [P-7 목차설계](../prompts/P07_목차설계.md) 의 **사업화 매핑 블록**을 사용하세요.

## Step 5. 과장 위험 점검

**목적** — 논문과 사업화 문서 모두에서 검증되지 않은 주장이나 근거 없는 표현은 심사 탈락·신뢰도 하락의 주요 원인입니다. 작성 전 위험 표현을 미리 점검합니다.

### 5-1. 검증 불가 주장 체크

아래 표현이 내 논문 또는 사업화 문서에 포함될 예정이라면, 검증 근거를 반드시 확보하세요.

| 위험 표현 유형 | 예시 | 포함 예정? | 검증 근거 확보 여부 |
|-------------|------|-----------|------------------|
| 절대적 최상급 | "세계 최초", "국내 유일" | ☐ 예 / ☐ 아니오 | ☐ 확보 / ☐ 미확보 |
| 과도한 성능 수치 | "정확도 99% 달성" | ☐ 예 / ☐ 아니오 | ☐ 확보 / ☐ 미확보 |
| 검증 없는 시장 규모 | "2030년 1조 원 시장" | ☐ 예 / ☐ 아니오 | ☐ 확보 / ☐ 미확보 |
| 인과 관계 과잉 주장 | "~하면 반드시 ~된다" | ☐ 예 / ☐ 아니오 | ☐ 확보 / ☐ 미확보 |
| 일반화 오류 | "모든 사용자에게 효과적" | ☐ 예 / ☐ 아니오 | ☐ 확보 / ☐ 미확보 |
| 출처 없는 통계 | "전문가의 80%가 동의" | ☐ 예 / ☐ 아니오 | ☐ 확보 / ☐ 미확보 |

### 5-2. 근거 없는 사업화 표현 체크

| 체크 항목 | 해당 여부 | 수정 방향 |
|---------|---------|---------|
| 특허 없이 "특허 기술" 언급 | ☐ 해당 / ☐ 무관 | |
| 파트너십 확정 전 "MOU 체결 예정" 표현 | ☐ 해당 / ☐ 무관 | |
| 투자 유치 전 "투자 확보" 표현 | ☐ 해당 / ☐ 무관 | |
| 시제품 없이 "출시 준비 완료" 표현 | ☐ 해당 / ☐ 무관 | |
| 임상·실증 없이 "효과 검증 완료" 표현 | ☐ 해당 / ☐ 무관 | |
| 법적 검토 없이 규제 면제 가정 | ☐ 해당 / ☐ 무관 | |

### 5-3. 표현 순화 연습

과장 표현을 학술·사업 문서에 적합하게 수정하는 연습입니다.

| 과장 표현 (예시) | 수정 표현 (직접 기입) |
|---------------|-------------------|
| "혁신적인 기술로 시장을 선도할 것이다" | |
| "본 연구는 모든 문제를 해결한다" | |
| "기존 방법보다 월등히 우수하다" | |
| "사용자 만족도가 극적으로 향상된다" | |

> **가이드** — 수정 방향은 수치 기반, 조건 명시, 비교 대상 특정으로 요약됩니다. 예: "혁신적"→"기존 A 방법 대비 B 지표에서 X% 향상", "모든"→"본 연구의 대상 집단인 [조건]에서"

> **연결 프롬프트** — [P-7 목차설계](../prompts/P07_목차설계.md) 의 **검증 점검 블록**에 자신의 표현을 붙여 넣고 피드백을 요청하세요.
